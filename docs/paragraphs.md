# 段落与结构保真（issue #84 第一块）

本文记录 `V..pdf` → EPUB 的第一项结构改进：**把"识别出来的行"还原成"读者看到的段落"**。
识别准确率仍未测量（见 [Benchmark report](../benchmark/benchmark_report.md)）；
本文里的所有数字都是**结构层面**的实测，不含 CER。

## 1. 问题

旧导出把"一行 = 一段"当成默认：`VerifiedPage.lines` 是校对层接受的**文本行**，
导出直接一行一个 `<p>`。这对扫描书是错的，因为扫描书里的一次行折返（换行）
不是段落边界。实测（`benchmark/corpus/v/`，6 个真实页）：

| 度量 | 旧行为（一行一段） | 现在 |
| --- | ---: | ---: |
| 六个真值段落的可视行数 | 161 | 161 |
| EPUB 段落数 | 161 | **36** |
| 真值段落数 | — | 36 |
| 段落级完全一致 | — | **36 / 36 = 100%** |

旧行为的另一面是"句中截断"：`V.` 的 6 页里有 14 个 `<p>` 结束在一个句子中间
（`……她的身体不断地吸纳无生命` / `跳下床，手紧攥成拳头。特`）。
读者看到的是一本书的排版中间被塞进了硬换行。

## 2. 证据：断段靠什么判断

段落边界不是文本属性，是**版面属性**，所以规则必须吃几何与块标签。
`scribeforge.domain.paragraphs.assemble_paragraphs(lines, direction)` 的输入是
`TextLine(text, box, role)`，输出是 `Paragraph(role, text)`。

判定顺序（前者优先，命中即返回）：

| 序 | 证据 | 语义 |
| --- | --- | --- |
| 1 | `role` 变化 | 标题 / 脚注 / 正文各自成块 |
| 2 | `role` 独立（`LineRole.is_standalone`） | 相邻两个标题是两个标题，不合并 |
| 3 | 上一行为空白行 | 空行是显式分隔，但**不产生**空段 |
| 4 | 竖排：仅看句末标点 | 竖排一列是段落碎片，缩进/版心宽度不适用 |
| 5 | 无几何（只有文本） | 退化为标点断段（比一行一段接近真相） |
| 6 | 行距 > 1.6 × 中位行距 | 段间空距 |
| 7 | 本行缩进 **且** 上一行短 | 最常见的排版信号，两个证据一致 |
| 8 | 上一行以句末标点结尾 **且**（本行缩进 或 上一行短） | 句末标点需要排版佐证 |

三条容易写错的细节，都已经写成回归测试（`tests/test_paragraphs.py`）：

- **满行以 `。` 结尾不断段。** 中文排版里句号正好落在版口时，句子继续到下一行。
  只按标点断段的实现会在这里凭空切开一段，第二段的开头就是一个半句。规则 8 因此
  要求"标点 + 排版佐证"，而不是"标点即断"。
- **闭合标点独占一行时贴回上一句。** `"`、`」`、`』` 之类只有闭合符号的行不是
  新段落，它是上一句的收尾（`_closing_only()`），贴回并**结束**该段。
- **拼接不制造空格，只在必要时制造。** 中文行与行直接相接；仅当断点两侧都是
  ASCII 字母数字时补一个空格（`vector` 被行折返切开、`V.` 与下一行的英文词相邻）。
  这保持了"导出文本 = 接受的行"这一证据性质：除了这一个空格，字符集合不变。

## 3. 角色：标题与脚注不再混进正文

`LineRole` 有三值：`BODY` / `HEADING` / `FOOTNOTE`。它们由
`pipeline/assembly.py::_pair_role` 从两个引擎各自的 `BlockType` 推出
（`TITLE → HEADING`，`FOOTNOTE → FOOTNOTE`，两个引擎都查，优先级明确），
沿 `VerifiedPage.line_roles` 传到导出层：

| 角色 | EPUB | DOCX |
| --- | --- | --- |
| `BODY` | `<p>` | 默认段落 |
| `HEADING` | `<h2>` | `Heading2` 样式 |
| `FOOTNOTE` | `<aside epub:type="footnote">` | 上标（`vertAlign subscript`）小字 |

在旧实现里，章节名和脚注都是"更多正文段落"，阅读系统既无法给标题排版，
也无法把脚注挪到页边或弹注。这是一次性把结构信息带进导出层，而不是事后用
正则去猜哪个 `<p>` 长得像标题。

## 4. 证据链没有被改写

- `VerifiedPage.lines` **仍然是一行一条**，是校对层接受的证据，永不合并；
- 段落是**派生的读视图**（`VerifiedPage.blocks()` / `paragraphs()`）；
- `line_boxes` / `line_roles` 与 `lines` 一一对应，长度不符在构造时就
  `ValueError`；两者 `compare=False`，因为"页"的身份是接受的文本与方向，
  不是某个引擎给的框；
- 导出自检（`adapters/export_check.py`）按 XHTML section 的子元素顺序读回
  `h2` / `p` / `aside`，与 `page.blocks()` 逐块比较，未知元素直接
  `ExportIntegrityError`；比较前 `_squash()` 去空白，容忍拼接插入的那个空格，
  但**字符丢失仍然会报错**。

换句话说：段落化只改变了"怎么呈现"，没有改变"接受了哪些字"。

## 5. 怎么复现这些数字

```bash
# 规则本身（不需要语料）
pytest tests/test_paragraphs.py -q -m "not benchmark"

# 真实语料上的段落恢复率（需要 benchmark/corpus/v）
pytest tests/test_paragraphs.py -q -m benchmark

# 真实语料上的跨页续段：把页断点放进最长段落中部，看能否接回原段
pytest tests/test_flow.py -q -m benchmark --no-cov
```

`tests/test_paragraphs.py::_rebuild_page()` 把真值转录**按本书的版心（28 字）
重新折行**，再交给规则还原：文本是真的、段落边界是真的，只有行折返是合成的。
这正是"段落重建要撤销的东西"，也是当前环境（无 GPU、`V..pdf` 无文本层）
唯一可信的输入。夹具遵守两条排版事实，否则会伪造失败：

1. 首行缩进两字，所以首行容量是 28 − 2 = 26 字；
2. 拉丁词不在行末被拆开（无连字符的断词会把一个空格塞进文本）。

## 6. 已知边界（未完成）

- **跨页续段已合并，但只在章节文档里。** 第 30 页最后一行是
  `……手紧攥成拳头。特`，第 40 页开头是 `些爱。` —— 同一个句子被切在两页上。
  `--layout chapter`（有章节树时的默认值）把一章渲染成一个 XHTML 文档，
  `domain/flow.py` 按"上一页末行未收句且不短行 + 下一页首行不缩进"合并，
  每页留 `epub:type="pagebreak"` 标记；`--layout page` 仍是逐页对照，
  那种布局下一个段落物理上不可能跨文件闭合。规则与已知边界见
  [Export](./export.md)。
- **跨页合并的实测范围只有"页断点落在段中"这一种情形。**
  `tests/test_flow.py::test_a_real_page_turn_inside_a_paragraph_is_undone`
  把 `benchmark/corpus/v` 六页的真实转录按本书版心重新折行，再把页断点放进
  当页最长段落的中部：**6/6 页都把被切开的段落接回原段，段落总数不变、字符不丢**。
  文本、版心、缩进惯例是真的，**页断点的位置是测试选的**；真实相邻两页的转录
  对还没有成对跑过，所以本文档不报告"整本合并率"。
- **无几何时只能按标点断段。** 只上报纯文本的引擎（或旧 store）会退化为标点
  规则，"满行以句号结尾"会多切一刀。这是有意选择的降级方向：宁可多切，
  也不要一行一段。
- **目录页与诗歌行**的居中/短行可能被并成一段；等章节模型与页面角色模型
  （issue #87）落地后，这两类应改为按块处理。
- **段落恢复率的分母是 6 页 36 段。** 它测的是"规则 + 版面几何"的重建能力，
  不是识别能力；换一本书（不同版心、不同缩进惯例）需要重新取样。
