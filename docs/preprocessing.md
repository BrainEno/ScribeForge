# 预处理层（PREPROCESS 阶段）

对应 issue #85。本文记录：为什么扫描旧书需要在 OCR 前插一层预处理、这一层具体做什么、
哪些结论来自对 `benchmark/V..pdf` 真实页面的实测、以及边界在哪。

## 1. 为什么需要这一层

在基准语料的评估中，旧书/古籍识别失败的原因往往不在模型，而在像素：

| 失效模式 | 对 OCR 的直接后果 |
| --- | --- |
| 书脊阴影 / 扫描仪光照不均 | 全局二值化把亮侧背景当纸、暗侧正文当墨，整列字丢失或糊成块 |
| 页面歪斜 2–6° | 行检测错位、行框互相重叠，跨列合并，阅读顺序崩坏 |
| 油墨褪色、复印多代 | 笔画灰度接近纸色，引擎直接识别不出字 |
| 装订线/桌沿被扫入画面 | 检测器把边框当文本块，浪费算力并污染版面分析 |

这些都不是"换更强的模型"能解决的：模型拿到的是已经被毁坏的证据。

## 2. 阶段位置与不变量

```
IMPORT → PREPROCESS → PRIMARY_OCR → SECONDARY_OCR → VERIFY → VLM_REVIEW
```

`JobStage.PREPROCESS` 是页面级阶段（`jobs.stage` 的 CHECK 约束需要重建表才能扩展，
所以 schema 升到 v5，见 `SQLiteStore._create_v5`）。

两条硬性不变量：

1. **原始位图是证据，永不修改。** 预处理是有损的（重采样、去噪）；原图保留意味着
   参数调错时可以直接重跑，而不必重新导入整本书。
2. **OCR 的归一化坐标属于"预处理后的画幅"。** 任何改变几何的变换（deskew、crop）
   都会移动坐标落点，所以给出坐标的那一帧必须同时用于生成复核裁片。否则复核者会被
   展示错位的像素——比不展示更糟。`process_page()` 因此让引擎与裁片共用同一路径与尺寸。

预处理结果与参数按页持久化在 `page_preprocess` 表（settings/applied/skew/输出 SHA-256/
尺寸/测量注记），重跑幂等：已存在的产物直接复用，**不会二次旋转**（二次旋转是静默破坏）。

## 3. 变换与它们的实测依据

| 变换 | 默认 | 作用 |
| --- | --- | --- |
| `deskew` | 开 | 投影剖面法测斜，仅当测得角度非零才旋转 |
| `deshadow` | 开（按页判定） | 除以背景模糊（低频照明）→ 抹平书脊渐变 |
| `contrast` | 开（按页判定） | `autocontrast` 拉伸色阶 |
| `denoise` | **关** | 3/5 中值滤波 |
| `binarize` | **关** | 逐列照明归一化后 Otsu 二值化 |
| `crop_border` | **关** | 裁掉均匀边距（保留 1% 安全边） |

### 3.1 为什么 denoise 默认关闭

在真实 300 DPI 页面 `benchmark/corpus/v/images/page_010.png` 上逐项实测
（墨/纸分离度，灰阶）：

| 变换 | 分离度变化 |
| --- | --- |
| deshadow | 225.8 → 227.1（**+1.3**） |
| denoise（median 3） | 225.8 → **222.6（−3.2）** |
| contrast | 225.8 → 225.8（0.0） |
| binarize | 225.8 → 255.0（+29.2，但丢弃灰阶证据） |

这个分辨率下笔画只有几个像素宽，中值滤波侵蚀的正是引擎要分辨的信号。因此 denoise
留作显式选项：它属于"确实有椒盐噪声/压缩损伤"的页面，不属于默认路径。
`binarize` 同理默认关闭——二值化丢掉复核者与 VLM 阶段所依赖的灰阶证据。

### 3.2 歪斜估计的三个坑（都由实测发现）

1. **重采样会伪造歪斜。** 用剖面方差直接比较各角度，会把双线性插值造成的边缘扩散当成
   对齐改善：在**本不可能有歪斜**的 PDF 渲染页上，±0.5° 的方差反而比 0° 高约 5%。
   修正：改用归一化剖面方差 `var/mean²`。修正后这 6 页全部测得 0.00°，而有真实歪斜的
   合成页面仍精确测得 −3.00°/−6.00°。
2. **全局阈值会被阴影带偏。** 书脊阴影让暗侧失墨、亮侧多墨，剖面被扭曲，估计器把
   **本来是正的页面**旋转到搜索上限（实测饱和到 8.00°）。修正：任何阈值化之前先做
   **逐列照明归一化**（除以该列 95 分位背景）。
3. **阈值量化必须一致。** Otsu 在 `uint8` 上建直方图，调用方却拿 float 数组比较：
   一个被归一化到 174.096 的墨色对阈值 174 判为"非墨"，掩膜为空，整个估计器静默失效。
   修正：`threshold_mask()` 先量化再比较，全流程共用。

### 3.3 按页判定（不要损坏干净页面）

`measure_degradation()` 在降采样副本上测背景均匀度，在**原始分辨率**上测墨迹暗部
（`dark_point`，墨迹 5 分位）：

- `needs_deshadow`：逐列背景 p95−p5 ≥ 4 灰阶
- `needs_contrast`：`dark_point` > 60

`dark_point` 必须在原始分辨率上测：降采样会把抗锯齿边缘平均进墨迹掩膜，让每一张好扫描
都显得"褪色"（6 页基准语的降采样测得墨色均值 104–117，而原始分辨率下墨迹 5 分位为 0）。
按降采样数据设阈值会把完好页面误判成需要修复。

因此**在 6 页真实基准语料上，默认流程是逐字节无操作**（`applied=[]`，输出与原图完全一致）。
这是正确行为，不是缺陷：干净页面不该被白白模糊一次。显式的操作符请求（如 `--preprocess-binarize`、
显式 `denoise`）不受按页判定影响。

## 4. 退化套件基准（真实页面派生）

干净语料无法验证修复能力，因此 `benchmark/analysis/preprocess_benchmark.py` 从**真实
基准页**派生确定性退化（固定随机种子），测量"是否测出损伤"与"修复是否把页面拉回"。
6 页 × 8 个变体，输出 `benchmark/analysis/preprocess_measurements.json`。

墨/纸分离度（灰阶，6 页均值），残余歪斜为 6 页最大绝对值：

| 变体 | 触发的变换 | 退化后 | 修复后 | 残余歪斜 |
| --- | --- | --- | --- | --- |
| clean | 无 | 227.9 | 227.9 | 0.00° |
| skew-3deg | deskew | 226.6 | 226.1 | 0.00° |
| skew-6deg | deskew | 226.6 | 226.1 | 0.00° |
| spine-shadow | deshadow | 191.5 | **228.8** | 0.00° |
| faded | contrast | 0.0 | **228.6** | 0.00° |
| speckled | 无（denoise 默认关） | 221.8 | 221.8 | 0.00° |
| speckled+denoise | denoise | 221.8 | 224.7 | 0.00° |
| skew-and-shadow | deskew + deshadow | 192.0 | 222.8 | 0.50° |

结论：歪斜、阴影、褪色三类真实退化均可被检出并基本完全修复；"歪斜+阴影"的组合修复后
残余 0.5°，仍在可接受范围。椒盐噪声默认不处理，开启 denoise 后 +2.9 分离度。

重新生成：

```bash
python benchmark/analysis/preprocess_benchmark.py
```

## 5. 边界与后续

本层只做**确定性的、可解释的经典算法**（numpy + Pillow），不调用任何模型：

- 不做透视纠正（书页弯曲/曲面展平），那是 #90 技术路线里需要评估的独立课题。
- 不做彩色/多光谱通道利用（古籍常用朱笔圈点、双色套印）；目前统一转灰度。
- 不做装订线分割与双页切分。
- `crop_border` 会改变画幅，默认关闭；开启时坐标仍相对裁剪后画幅，记录在证据里。

上游依赖：`numpy>=1.26`（新增直接依赖，此前仅作为 Pillow/pypdfium2 的间接依赖存在，
不应依赖传递依赖）。

### 已记录预处理图的恢复与校验

重新处理已有页时，预处理参数必须与已记录参数一致；若参数不同，请恢复原参数或新建项目，
不能静默用新参数解释旧 OCR。复用预处理图前核对 SHA-256，失配时停止并提示从备份恢复。
如果文件丢失，可以尝试用原参数重新生成，但只有生成内容的摘要与旧记录完全一致才写回原路径；
否则停止并保留旧的证据记录。独立 `repair` 在裁切原始页图前也会校验已有的页图摘要；
旧项目没有摘要时，仍遵循既有的兼容策略，无法证明该页图未被更改。

自 schema v13 起，新整页 OCR 运行记录输入帧类型、摘要及尺寸。repair 与 VLM 使用
两个 OCR run 共同绑定且经校验的帧；原图与预处理图不再共用未经转换的坐标。
旧项目的历史 run 未记录输入帧，迁移时保持未知并拒绝自动重读；复核 JSON 会明确
标注 `coordinate_frame: unknown`，不提供未经验证的裁剪图。为使用自动重读，请将源文件
重新导入新项目或恢复带明确帧记录的备份；原历史证据不会被覆盖。

自 schema v14 起，新区域重读与 VLM 裁剪另行记录输入裁剪摘要、页帧摘要、像素矩形
和缩放倍率。每次模型调用使用独立裁剪文件，不覆盖之前的裁剪；旧裁剪若没有几何
绑定仍是未知证据，不会在迁移时猜测。详情见数据模型文档。

桌面 Tk 复核的坐标叠加使用经过验证的 OCR 坐标帧；原始页在单独的无叠加页签中显示。
若帧未知或无法校验，坐标帧页不展示叠加，也不将未知裁剪作为可信图片展示。
