# 页眉页脚剔除（issue #89）

## 1. 问题

旧书每一页都有"不是正文"的行：书名缩写页眉（本书是 `V.`）、部名/篇名、出版社行、
印刷页码。它们出现在 500+ 页上，会造成三种损害：

1. **导出错误**：重排后的 EPUB 里每两句话之间插一句 `V.` 或 `23`；
2. **复核污染**：引擎对页眉的读法稍有差异（`V.` vs `W.`）就产生一个复核条目，
   562 页就是 562 个无意义条目，把真正的分歧淹没；
3. **结构误判**：页眉里的数字/罗马数字被当成页码（#87 的序列规则是其最后一道防线）。

## 2. 检测规则：只认三类证据

`domain/furniture.py::detect_page_furniture` 对每一行判断，**任一**成立即为页眉页脚：

| 规则 | 依据 | 目的 |
| --- | --- | --- |
| `engine_block` | 引擎声明为 `header`/`footer` 块（#86 契约 v2） | 引擎已完成版面分类，直接采信 |
| `repeated_in_margin` | 位于页边带（上下 8%）**且**全书出现 ≥3 页 | 页眉的本质是**跨页重复** |
| `page_number` | 位于页边带且能被解析为孤立页码 | 印刷页码 |

三条否决规则（宁可不删，不可误删）：

- **单行页面不删**：页面上只有一行时，它是内容而不是"相对其他行而言的装饰"；
- **只在 1 页出现的页边行不删**：那正是章标题的形状；
- **正文区（中间 84%）不删**：反复出现的副歌式正文不属于页眉页脚。

跨页重复按**折叠后文本**比较（#88），所以两个引擎分别读成 `說`/`说` 的同一页眉
仍然被判定为同一条。

## 3. 应用位置

| 环节 | 行为 |
| --- | --- |
| `assemble_verified_content` | 页眉页脚对应的 pair **不导出**，且**不要求有决策**（不会因此阻塞导出） |
| 导出报告 | 打印被剔除的行数与原因分类；`VerifiedBook.dropped_furniture` 保留每条的页码/文本/原因 |
| `review_queue` | 页眉页脚的 pair 不进入复核队列（检测是全书性的，无法在单页处理时进行） |

关键设计取舍：**剔除是可报告的，不是静默的**。`DroppedFurniture(page_index, text, reason)`
随书返回，CLI 会输出
`excluded 562 page-furniture line(s) (page_number 540, repeated_in_margin 22)`。
静默删文本正是这一层最容易犯的错。

## 4. 已知歧义：`V.`

本书页眉就是书名 `V.`，而 `V` 同时是合法的罗马数字 5。因此它会被判为 `page_number`
而不是 `repeated_in_margin`——**结果相同**（都会被剔除），但原因不同，且这一歧义会
影响 #87 的页码识别。

防线在 #87：页码必须构成**单调序列**才被接受，且单点序列整体丢弃。若某段 3 页的页眉
全是 `V.`（页码相同、不递增），序列解析会把它拆成 3 个单点段并全部丢弃，因此不会被
误当作印刷页码。此行为有测试固定（`test_a_running_head_that_looks_like_a_roman_numeral_is_still_removed`）。

## 5. 边界

- 页边带阈值固定 8%：排版特别的书（页眉压进正文区）不会被识别为页边行，
  但也不会误删正文；这两者之间的取舍偏保守。
- 只出现 2 页的重复页边行不删（可能是跨页的部名）。
- 未处理"左右页交替页眉"（奇数页书名、偶数页章名的传统排版）：两套页眉各自达到
  3 页重复即会被识别，但若某套只在 2 页出现则保留。
- 未处理页脚中的书名与页码同行（`V. 23`）：整行会被判为页边重复行或页码之一，
  具体取决于解析结果。
